Purpose

Make the Forge PGE autonomy loop (PR #5 branch agent/standalone-a2a-auth) actually runnable end-to-end with gemma4:12b-mlx served by Ollama, then execute and score the canonical 8-goal suite (snake game, ML experiment loop, LRU cache, RPN calculator, JSON parser, tic-tac-toe engine, Dijkstra, JS email validator). Two verified defects currently make this impossible: (1) run_pge.py silently discards CLI-supplied goals when the default project has history, and (2) the consolidated LLM client in forge_runtime/llm.py uses an OpenAI structured-output dialect and a reasoning_effort:"none" flag that together guarantee unparseable output from Gemma models on Ollama.

Problem

Three defects, all reproduced live in session d44f5f39 on 2026-07-11:

  • P1 — CLI goal silently discarded. run_pge.py builds the --goal only as an in-memory Pydantic Goal and applies it via state_goal = db_goal or goal (run_pge.py:190). resolve_default_project() reuses the oldest project named "default", and active_goal_query() (engine/src/runtime.py:15) falls back to the newest goal of any status. Net effect: if the default project's newest goal is completed, the loop prints 🏁 Persisted goal is verified complete. after 0 batches and exits — the new goal never runs. Reproduced: "Build a Python Snake game" exited instantly against project b240abae whose fizzbuzz goal was completed on 2026-07-03.
  • P2 — structured output never constrained on Ollama. forge_runtime/llm.py:71-76 sends OpenAI-style response_format:{type:"json_schema",…} to /v1/chat/completions — Ollama's OpenAI-compat layer ignores/garbles it (ollama#10937). It also always sends extra_body:{"reasoning_effort":"none"}, which maps to think=false — a known Ollama bug for Gemma-family thinking templates where the end-of-thinking token never fires so grammar masking is never applied (ollama#15260). Result: reasoning prose + ```json fences + a foreign action/action_input vocabulary. Measured: 0/8 eval fixtures pass (evals/results/gemma4-12b-mlx-ollama.json). The codebase already learned this once — engine/src/auditor.py:219 ("response_format json_schema is NOT sent — Ollama cloud ignores or garbles it, verified 2026-06-12") — but PR #5's consolidated client reintroduced both triggers for planner/executor/evaluator.
  • P3 — nested schemas break the Ollama-MLX grammar engine; executor parser is fragile. Verified against the live model: Ollama's native /api/chat with a nested JSON schema (objects containing required arrays) silently falls back to unconstrained text on the MLX backend, while flat format:"json" plus the schema stated in the prompt yields clean, valid JSON with thinking separated into message.thinking. Additionally executor_node.py:410-431 strips fences but lacks the first-brace/last-brace extraction fallback that planner_node.py:296 and evaluator_node.py:566 both have.

Solution

Four surgical changes, then the suite run. (1) Persist CLI goals: when --goal is passed, run_pge.py creates a real ForgeGoal row via the existing MemoryService.create_goal() (the same path the A2A bridge uses at forge_a2a/task_bridge.py:70), and gains a --new-project flag that creates a fresh project + workspace per goal. (2) Teach forge_runtime/llm.py an Ollama dialect: auto-detected (or forced via FORGE_LLM_DIALECT=ollama), it POSTs to the native /api/chat with format:"json" when a schema is requested, embeds the schema as prompt text (per Ollama docs), and omits think/reasoning_effort entirely. Non-Ollama backends keep today's path. (3) Harden parsing: a shared extract_json() helper (fences → think-tags → brace-window) used by the executor node and the eval script. (4) Align evals/model_incident_eval.py to the same dialect and gate on 8/8 before burning hours on real goals. Then a new suite runner executes the 8 goals sequentially in fresh projects, bounded by turn and wall-clock budgets, and writes a scored report.

Notes

Verified evidence (session d44f5f39, 2026-07-11)

  • Live curl to native /api/chat + format:"json" (no think): clean single-object JSON in message.content, reasoning isolated in message.thinking. Same call with the nested executor schema as format: constraint silently dropped, output reverted to action/action_input + fences. This is why the plan uses flat format:"json" + prompt grounding, not schema-as-grammar.
  • /v1/chat/completions + response_format json_schema + reasoning_effort:"none": 0/8 fixtures (artifact evals/results/gemma4-12b-mlx-ollama.json). Prior LM Studio artifact gemma-4-12b-qat.json shows the same prose-prefix signature (0/5) — the openai-dialect fix may help LM Studio too, but that is out of scope here.
  • P1 reproduction: snake-game run exited "verified complete" after 0 batches against project b240abae (completed fizzbuzz goal from 2026-07-03).

Research sources

  • ollama#15260 — think=false breaks format on Gemma-family templates (masking deferred past a token that never comes). Workaround: omit think.
  • ollama#10937 / #10001 — OpenAI response_format json_schema ignored on /v1; use native format.
  • Ollama structured-outputs docs — recommends passing the schema as prompt text alongside format.
  • In-repo precedent: engine/src/auditor.py:219 (2026-06-12) — auditor already dropped response_format for Ollama and parses defensively. Phase 2 generalizes that lesson to the whole engine.
