Purpose

Upgrade Forge's memory subsystem from "efficient storage + retrieval" (shipped in agent-memory-efficiency) to the mechanisms the literature shows actually make long-horizon agents better: recency-decayed relevance scoring and reflection (Generative Agents), linked and evolving memory notes (A-MEM, HippoRAG), agent-directed context paging (MemGPT), verbal self-reflection on failure (Reflexion), and event-history replay as the durability ground truth (Durable Functions, Beldi). Every mechanism is pinned to a saved paper in AI_DOCS/research/ so the design rationale is auditable.

Problem

The v1 work made memory cheap and durable, but five gaps remain when measured against the saved research:

#GapPaper that names itWhere in Forge
1Retrieval scores similarity + importance + confidence but has no recency decay, and budgets one flat pool rather than per memory class (episodic/semantic/procedural)generative-agents-2023, coala-2023app/services/memory_retrieval.py
2Memories are isolated rows: no links between related notes, no evolution of old notes when new ones arrive, retrieval can't follow associationsa-mem-2025, hipporag-2024hermes_memory_items (has tags/embedding/supersedes, unused for linking)
3Memory is push-only: the steward decides what the executor sees; the executor cannot request a memory it knows it needs mid-taskmemgpt-2023executor tool list (engine/src/nodes/executor_node.py) has no recall tool
4Lesson extraction is a deterministic template ("run X and fix this first") — no verbal reflection over why the attempt failed, which is where Reflexion's gains come fromreflexion-2023engine/src/nodes/evaluator_node.py lesson block
5Checkpoints are trusted but never validated against the event history; there is no replay path, so a corrupted checkpoint is silently authoritativedurable-functions-2021, beldi-2020, netherite-2022hermes_checkpoints vs hermes_events; Experiment D in docs/DURABLE_SUBSTRATE.md is unstarted

Solution

Five phases, one per gap, all built on the schema and modules that already exist (no migrations needed — links ride in tags, reflections are lesson rows, replay is read-only). Each phase keeps the repo invariant: best-effort, deterministic fallback, never block the loop. Phase order is dependency order: scoring first (everything retrieves through it), then links (retrieval expansion), then the recall tool (uses both), then reflection (writes into the same store), then replay (independent, riskiest, last).

[x] Phase 1: Generative-Agents Scoring — recency decay + CoALA class budgets

generative-agents-2023 retrieves by recency × importance × relevance with exponential recency decay; coala-2023 argues memory classes deserve separate treatment. Forge's blend has two of the three terms and one flat budget.

1. Add the recency term

  • [x] In memory_retrieval.py, add W_RECENCY = 0.15 (renormalize: similarity .5, importance .2, confidence .15, recency .15) and a decay expression exp(-age_hours / half_life) with FORGE_MEMORY_RECENCY_HALFLIFE_HOURS (default 72). SQL tier uses extract(epoch from now() - created_at); the recency term computes in Python for tier 3 so SQLite stays supported.
  • [x] Constraints are exempt from decay (a non-negotiable constraint never gets stale) — skip the term when memory_type == "constraint".

2. Per-class budgets (CoALA lanes)

  • [x] Map existing memory_types: episodic = {mistake, learning_*, task_consolidation}, semantic = {decision, constraint, next_action, bug, blocker}, procedural = {lesson, learning_distill}. Pure function memory_class(memory_type) with an "episodic" default.
  • [x] Replace the single 6000-char cut with lane budgets (semantic 3000 / procedural 1500 / episodic 1500, env-tunable) applied after ranking, so one noisy class can no longer evict the others — the failure mode CoALA's taxonomy predicts.

3. Testing Strategy

Pure-logic tests on the SQLite fixture: frozen timestamps, deterministic scores. Edge cases: all-one-class pools (unused lane budget spills over), constraint exemption, zero half-life guard.

  • [x] uv run pytest tests/test_memory_retrieval.py -q — v1 behavior contracts still hold.

[x] Phase 2: A-MEM Links + HippoRAG 1-hop Expansion

a-mem-2025: new memories generate links to related old ones and can trigger evolution of their content; hipporag-2024: association-following retrieval beats flat vector search on multi-hop questions. Forge memories are isolated rows.

1. Deterministic link generation on write (app/services/memory_links.py)

  • [x] generate_links(db, item, k=3): candidate = same project, active, share ≥1 non-fp: tag OR same file_path OR cosine ≥ 0.75 (Postgres only). Store as link:<id> entries appended to tags on both rows (bidirectional), capped at 8 links/row. No LLM call — deterministic per the repo invariant; A-MEM's LLM link judgment is a later upgrade, not a dependency.
  • [x] Call from record_memory_item, best-effort (wrapped, never blocks the write).

2. 1-hop retrieval expansion

  • [x] expand_hits(db, items, budget): collect link: targets of ranked hits, fetch active ones not already selected, append lowest-priority within the remaining lane budget. Wire into select_memories behind FORGE_MEMORY_LINK_EXPANSION (default on).

3. Evolution pass (hygiene)

  • [x] evolve_memories(db, project_id, batch=8): when a new mistake/lesson links to an older item of the same type, append a one-line [update <date>] superseded context: <summary> suffix to the older row (never rewrite its body; never touch constraints/decisions — authority-bearing types are immutable). Run from run_batch_hygiene.

4. Testing Strategy

SQLite fixture; embeddings stubbed. Edge cases: link cap enforcement, bidirectionality after one-sided delete/archive, expansion respecting lane budget, evolution skipping protected types.

[x] Phase 3: MemGPT Paging — the recall_memory executor tool

[x] Phase 4: Reflexion — verbal self-reflection on repeated failure

reflexion-2023: converting failure signal into a written self-reflection, stored and re-injected on retry, outperforms blind retries. Forge's current lesson text is a fixed template; the reflection step is where the paper's gains live.

1. LLM reflection with deterministic fallback

  • [x] In the evaluator's lesson block: on second-plus recurrence, prompt the evaluator's existing model client with the failing test output + the executor's last actions: "In two sentences: (1) why did this attempt fail, (2) what should the next attempt do differently. No restatement of the error." Parse into observation/prevention; on any failure fall back to the current template text (the shipped behavior becomes the fallback, keeping the never-block invariant).
  • [x] Reuse forge_runtime.lessons.extract_lesson validation (min length, not-a-restatement) so vacuous reflections are rejected before storage.

[x] Phase 5: Durable-Functions Replay — event history as ground truth

durable-functions-2021 proves in-flight state is reconstructible by deterministically replaying persisted step results; beldi-2020 adds idempotency keys per step; netherite-2022 shows the log is the scalable substrate. Forge trusts checkpoints it never validates — this phase makes the event log the auditor of the checkpoint, without changing how the loop runs.

1. Read-only projection (forge_runtime/replay.py)

  • [x] replay_state(db, project_id, goal_id=None): fold hermes_events (+ task/file/test rows as materialized step results) in created_at order into a projection {task statuses, last verdict, files touched, tests passed}. Pure fold, no LLM, no writes.
  • [x] diff_checkpoint(projection, checkpoint): structural diff against the latest hermes_checkpoints.current_state; returns a list of divergences (missing task, contradictory status, phantom completion).

2. Replay audit at batch boundary + step idempotency keys

  • [x] In run_batch_hygiene: run the diff; log divergences as a mistake memory (importance 5, tag replay-divergence) — surfaced to the next cycle's pack instead of silently trusting the checkpoint. Never auto-corrects; a divergence is evidence for the loop, not an action.
  • [x] Beldi discipline: executor file-write events gain an idempotency key task_id:path:content_sha in event_metadata, making replay folds deduplicate crash-duplicated writes correctly.

3. Testing Strategy

Synthetic event streams on the SQLite fixture. Edge cases: empty history, duplicated write events (idempotency dedupe), checkpoint that claims a completion the events don't support (flagged), out-of-order timestamps (stable fold by created_at, id tiebreak).

Dependencies: none new. All phases run on the stock SQLite-testable schema; no migrations (links live in tags, reflections are lesson rows, replay is read-only). The durable-substrate profile from v1 is complementary, not required.

Sequencing rationale: Phases 1–2 change what retrieval returns (measurable via existing pack telemetry in hermes_context_pack_logs — compare selected-id relevance before/after on the same goals). Phase 3 is the first agent-visible change. Phase 4 adds the only new LLM call, recurrence-gated. Phase 5 touches nothing on the hot path and is pure added observability — lowest regression risk, saved for last so its audit can watch the four phases before it.
